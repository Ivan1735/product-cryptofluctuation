# План навчального випуску

## Об’єкт і рішення

Випуск **документації продукту**, не публічного торгового сервісу.
Цільова версія: **v1.0.0**, SemVer. Іван доручив завершити й опублікувати комплект;
це не погодження викладача або формальне приймання всіма учасниками.
Оригінальний гайд «ТСПП: проєкт продукту — документи і роадмап», 13.10.2026,
отримано від Івана 01.11.2026. Джерело доступу до курсу: <https://edu.happ.tools/help>.

Наявний [ZIP](../4-quality/CryptoFluctuation_BUG001-004_fixed.zip) — додатковий робочий прототип;
його треба розпакувати окремо. Checkout документації сервер не запускає.
Перший MVP — FR-01–08; ширші можливості ZIP не розширюють автоматично обсяг.

## Правильне тлумачення обсягів

У гайді кількості — **орієнтир**, не дозвіл вигадувати результати.
Є 18 FR, 6 NFR, 31 TC, 6 QT, додаткові 15 UT-специфікацій,
3 ADR, 6 модулів та реєстр статичних зауважень.
Виявлено 4 реальні баги, а не 8 штучно створених.
Орієнтир «10+» стосується **зауважень у review-report**, не кількості GitHub-коментарів.
Два фактичні людські коментарі PR №1 збережені окремо від статичного перегляду асистента.
Інтерв’ю, personas, CJM, usability-test, pitch, roadmap, retro та privacy — додаткові.
NFR-04 лишається непідтвердженою продуктовою вимогою; це не приховується.

## Перевірки й критерій передачі

1. Базові матеріали доступні через README; діаграми й локальні посилання читаються.
2. Є інтерфейсні/негативні тестові специфікації та фактичний звіт інтеграційних і системних підсценаріїв.
3. Результати копій не змішані: [повторний прогін](../4-quality/qa-known-bugs-retest.md)
   — 41/41 unittest та 15/15 helper-сценаріїв, **не 37/37 канонічних TC/QT**.
4. Збережені початкові провали, реальні коментарі та відкриті питання.
5. Виконано Git-вправу з реальним конфліктом, ручним рішенням та merge-комітом.
6. На точному кінцевому main успішні Markdown і локальні посилання в Actions.
   Зовнішні URL — інформаційна перевірка з можливими мережевими блокуваннями.
7. Тег і Release посилаються на перевірений commit; опис містить результати й обмеження.
8. Іван підтверджує правильний акаунт викладача, доступ та подання на платформі.

Стан пунктів 5–8 звіряється з фактичними посиланнями; план не є доказом їх виконання.
Технічний випуск не оголошує роботу оціненою або всі NFR виконаними.

зазначенням, якщо кілька етапів завершуються одним пакетом. Не імітуються
старі дати проходження чи схвалення викладача. Після публікації тег не пересувається.
Патч документації — v1.0.1, розширення — v1.1.0, несумісна зміна — v2.0.0.
Версія документації не прирівнюється до версії ZIP, яку користувач називав 0.1.

## Середовище, стратегія й відкат

Документація: GitHub Markdown/Mermaid/PNG. Прототип: локальні Python/Flask/SQLite,
[версії перевіреного середовища](../2-architecture/modules.md), Chromium для автоматизації.
Перед релізом — гілка → PR → CI → merge → CI main → незмінні теги → GitHub Release.
Код не розгортається в інтернет; секрети й робоча БД не включаються.

Помилку виправляють новим PR та патч-версією; старі теги не переміщують.
За серйозної помилки повертаються до попереднього commit окремим revert і повторюють CI.
Відкат Git **не відновлює SQLite**: для неї потрібні зупинка, backup і тест відновлення.

## Відомі обмеження

- Не всі TC/QT виконано, немає людського usability-дослідження або сертифікації безпеки.
- Немає гарантій прибутковості, свіжості всіх постачальників та доступності RSS/CDN.
- Проєктний `/api/v1` не є точним переліком маршрутів ZIP; нові UT — специфікації.
- Пороги UI 60 с / дослідження 35 с відокремлені; погодження викладача не заявлено.
- Нові повідомлення UA/EN, інші мови — EN fallback; Tailwind CDN не зафіксований.
- Повторний людський перегляд найновіших змін не приписано авторам коментарів PR №1.

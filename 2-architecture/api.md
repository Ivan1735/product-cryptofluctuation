# Контракт API

## 1. Статус документа

Версія 0.1 — проєкт контракту для обговорення.

Документ описує очікувані HTTP-запити, відповіді та помилки.
Наявність маршруту в документі не означає,
що його вже реалізовано або перевірено.

Приклади містять умовні дані.
Ціни, ідентифікатори й часові позначки
не є поточними ринковими спостереженнями.

## 2. Загальні правила

Запропонований префікс: /api/v1.

Формат даних: JSON.
Кодування: UTF-8.
Для запитів із тілом: Content-Type: application/json.

Час передається у форматі ISO 8601 з часовою зоною UTC.

Ціни та кількості передаються десятковими рядками,
щоб контракт не залежав від округлення чисел JSON.

Відсутні значення передаються як null,
а не як нуль або порожній рядок.

API призначений для локального навчального використання.
Авторизація в поточному обсязі не передбачена.
Відкривати такий API для загального доступу не планується.

## 3. Версіонування

Префікс /api/v1 позначає основну версію контракту.

Додавання необов’язкового поля може виконуватися в межах v1.
Видалення поля, зміна його типу або несумісна зміна поведінки
потребують нової основної версії.

Зміни контракту потрібно відображати
в журналі змін і пов’язаних перевірках.

## 4. Перелік операцій

| Метод | Маршрут | Призначення | Обсяг |
|---|---|---|---|
| GET | /assets | Список і пошук активів | Must |
| GET | /quotes | Котирування та стан даних | Must |
| GET | /candles | Дані графіка | Must |
| GET | /news | Новини та походження посилань | Must |
| GET | /signals | Журнал сигналів | Should |
| GET | /signals/{signalId} | Початкові умови та результати сигналу | Should |
| GET | /paper-positions | Активні навчальні позиції | Should |
| POST | /paper-positions | Додати навчальну позицію | Should |
| POST | /paper-positions/{positionId}/close | Закрити навчальну позицію | Should |
| DELETE | /paper-positions/{positionId} | Видалити помилкову позицію | Should |
| POST | /paper-trades/reset | Скинути навчальні угоди | Should |
| GET | /paper-statistics | Місячна статистика | Should |

У таблиці маршрути наведено без префікса /api/v1.

Запис сигналів і оновлення їхніх результатів
є внутрішніми операціями системи.
Публічні маршрути довільного створення історичних сигналів
не передбачені.

## 5. Формат помилки

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Кількість має бути додатним числом.",
    "fields": {
      "quantity": "Має бути більше нуля."
    }
  }
}
```

Поле fields необов’язкове.
У відповідях не показуються SQL, секрети,
локальні шляхи та трасування внутрішніх помилок.

## 6. HTTP-коди

| Код | Значення |
|---|---|
| 200 | Запит успішно оброблено |
| 201 | Навчальну позицію створено |
| 204 | Помилкову позицію успішно видалено; тіло відповіді відсутнє |
| 400 | Некоректний JSON або параметр запиту |
| 404 | Актив чи запис не знайдено |
| 409 | Конфлікт стану, наприклад повторне закриття позиції |
| 422 | Поля мають недопустимі значення |
| 503 | Потрібне джерело або придатні дані недоступні |
| 500 | Внутрішня помилка, зокрема невдале збереження |

Порожній список сам собою не є помилкою.

## 7. GET /assets

Пов’язані вимоги: FR-01, FR-02.

Необов’язковий параметр query:
пошук за назвою або символом без залежності від регістру.

Приклад:

```http
GET /api/v1/assets?query=btc
```

Відповідь 200:

```json
{
  "data": [
    {
      "symbol": "BTC",
      "name": "Bitcoin",
      "marketPair": "BTCUSDT"
    }
  ]
}
```

Правила:

- Порожній query повертає всі 15 підтримуваних активів.
- Відсутність збігів повертає 200 і порожній масив data.
- Для позначення MATIC відповідь містить пару POLUSDT
  та пояснення міграції.

## 8. GET /quotes

Пов’язані вимоги: FR-01, FR-03, FR-08.

Приклад:

```http
GET /api/v1/quotes
```

Умовна відповідь 200:

```json
{
  "data": [
    {
      "symbol": "BTC",
      "marketPair": "BTCUSDT",
      "price": "100.00",
      "quoteCurrency": "USDT",
      "change1hPct": "-0.25",
      "source": "Binance",
      "receivedAt": "2026-01-01T12:00:00Z",
      "dataStatus": "fresh"
    }
  ],
  "meta": {
    "warnings": []
  }
}
```

Ціна в прикладі довільна.

Допустимі значення dataStatus:

- fresh — дані відповідають погодженій політиці актуальності;
- stale — збережені дані не відповідають цій політиці;
- demo — демонстраційні дані;
- unavailable — котирування недоступне.

Для unavailable числові поля можуть бути null.

Якщо доступні збережені значення, сервер може повернути 200
зі станом stale та попередженням.
Якщо придатної відповіді немає взагалі, повертається 503.

Точні пороги актуальності потрібно погодити окремо.
Час отримання не є гарантією часу формування ціни біржею.

Браузер планує опитування кожні 10 секунд
у видимій активній вкладці.
Сам GET не гарантує нового звернення до біржі.

## 9. GET /candles

Пов’язані вимоги: FR-04, FR-05, FR-08.

Обов’язкові параметри:

- symbol — підтримуваний символ активу;
- period — 1h, 4h, 1d або 7d.

Приклад:

```http
GET /api/v1/candles?symbol=BTC&period=1h
```

Умовна відповідь 200:

```json
{
  "data": {
    "symbol": "BTC",
    "marketPair": "BTCUSDT",
    "period": "1h",
    "source": "Binance",
    "receivedAt": "2026-01-01T12:00:00Z",
    "dataStatus": "fresh",
    "candles": [
      {
        "openTime": "2026-01-01T11:00:00Z",
        "open": "100.00",
        "high": "102.00",
        "low": "99.00",
        "close": "101.00",
        "volume": "12.50"
      }
    ]
  }
}
```

Приклад свічки показує лише структуру даних.

Помилки:

- 400 — відсутній або непідтримуваний period;
- 404 — непідтримуваний актив;
- 503 — дані графіка недоступні.

Порожній набір не подається як успішно завантажений графік.
Вигадані свічки не додаються.

## 10. GET /news

Пов’язані вимоги: FR-06, FR-07, FR-08.

Приклад:

```http
GET /api/v1/news
```

Умовна відповідь 200:

```json
{
  "data": [
    {
      "articleId": "article-example-1",
      "title": "Умовний заголовок для демонстрації формату",
      "publisher": "Example Publisher",
      "url": "https://example.org/article",
      "publishedAt": null,
      "fetchedAt": "2026-01-01T12:00:00Z",
      "provenance": {
        "https": true,
        "publisherDomainMatches": true,
        "contentFactChecked": false
      }
    }
  ],
  "meta": {
    "dataStatus": "fresh",
    "warnings": []
  }
}
```

Example Publisher і example.org — лише заповнювачі прикладу.
Робочі джерела: CoinTelegraph і CoinDesk.

Правила:

- Невідома дата передається як null.
- Відсутність публікацій повертає порожній масив.
- Перевірка домену не означає перевірки правдивості.
- За часткової недоступності повертаються доступні дані
  з відповідними попередженнями.
- За повної недоступності без збереженого списку повертається 503.

## 11. GET /signals

Пов’язані вимоги: FR-09, FR-10.

Повертає записи журналу.
Відсутність записів повертає 200 і порожній масив.

```http
GET /api/v1/signals
```

Умовна відповідь 200:

```json
{
  "data": [
    {
      "signalId": "signal-example-1",
      "symbol": "BTC",
      "createdAt": "2026-01-01T12:00:00Z",
      "entryPrice": "100.00",
      "kind": "risk",
      "rulesVersion": "rules-example"
    }
  ]
}
```

Перелік допустимих kind потрібно узгодити
з правилами аналізу до фіксації контракту.

## 12. GET /signals/{signalId}

Пов’язані вимоги: FR-09–FR-11.

```http
GET /api/v1/signals/signal-example-1
```

Умовна відповідь 200:

```json
{
  "data": {
    "signalId": "signal-example-1",
    "symbol": "BTC",
    "createdAt": "2026-01-01T12:00:00Z",
    "entryPrice": "100.00",
    "kind": "risk",
    "rulesVersion": "rules-example",
    "evidenceSnapshot": {
      "arguments": [],
      "risks": ["Умовне пояснення ризику"],
      "missingData": []
    },
    "outcomes": [
      {
        "horizonHours": 1,
        "targetTime": "2026-01-01T13:00:00Z",
        "observedAt": null,
        "observedPrice": null,
        "changePct": null,
        "status": "pending"
      }
    ]
  }
}
```

Допустимі горизонти: 1, 4 та 24 години.

Стани результату:

- pending — цільовий час ще не настав;
- unavailable — час настав, але потрібного спостереження немає;
- available — результат отримано.

Початковий знімок незмінний.
Невідомий signalId повертає 404.

## 13. GET /paper-positions

Пов’язані вимоги: FR-12–FR-14.

Повертає активні навчальні позиції.

```http
GET /api/v1/paper-positions
```

Умовна відповідь 200:

```json
{
  "data": [
    {
      "positionId": "position-example-1",
      "symbol": "BTC",
      "quantity": "0.10",
      "entryPrice": "100.00",
      "openedAt": "2026-01-01T12:00:00Z"
    }
  ]
}
```

За відсутності позицій data є порожнім масивом.

## 14. POST /paper-positions

Пов’язана вимога: FR-12.

```http
POST /api/v1/paper-positions
Content-Type: application/json
```

Тіло:

```json
{
  "symbol": "BTC",
  "quantity": "0.10",
  "entryPrice": "100.00"
}
```

Умовна відповідь 201:

```json
{
  "data": {
    "positionId": "position-example-1",
    "symbol": "BTC",
    "quantity": "0.10",
    "entryPrice": "100.00",
    "openedAt": "2026-01-01T12:00:00Z"
  }
}
```

Валідація:

- актив має бути підтримуваним;
- quantity та entryPrice — скінченні додатні десяткові значення;
- порожні, нечислові, нульові й від’ємні значення відхиляються;
- NaN та Infinity не допускаються.

Некоректні поля повертають 422 без створення запису.

## 15. POST /paper-positions/{positionId}/close

Пов’язана вимога: FR-13.

```http
POST /api/v1/paper-positions/position-example-1/close
```

Ціну закриття визначає сервер із придатних ринкових даних.
Довільна ціна закриття від клієнта не приймається.

Умовна відповідь 200:

```json
{
  "data": {
    "tradeId": "trade-example-1",
    "originalPositionId": "position-example-1",
    "symbol": "BTC",
    "quantity": "0.10",
    "entryPrice": "100.00",
    "exitPrice": "101.00",
    "grossResult": "0.10",
    "closedAt": "2026-01-01T13:00:00Z"
  }
}
```

Помилки:

- 404 — позиція невідома;
- 409 — позицію вже закрито;
- 503 — придатна ціна закриття недоступна;
- 500 — операцію не вдалося зберегти.

Повторний запит не створює другої завершеної угоди.
Створення історії та видалення активної позиції
виконуються узгоджено в транзакції.

## 16. DELETE /paper-positions/{positionId}

Пов’язана вимога: FR-14.

```http
DELETE /api/v1/paper-positions/position-example-1
```

Успішна відповідь: 204 без тіла.

Правила:

- видаляється активна помилкова позиція;
- завершена угода не створюється;
- результат інших угод не змінюється;
- невідома активна позиція повертає 404.

## 17. POST /paper-trades/reset

Пов’язана вимога: FR-15.

```http
POST /api/v1/paper-trades/reset
Content-Type: application/json
```

Тіло:

```json
{
  "confirmation": true
}
```

Відповідь 200:

```json
{
  "data": {
    "reset": true,
    "signalJournalPreserved": true
  }
}
```

Сервер приймає лише логічне значення true.

Відсутнє або false-підтвердження повертає 422 без змін.
Скасування в інтерфейсі взагалі не надсилає запит скидання.

Операція очищує активні та завершені навчальні угоди,
але не видаляє сигнали та їхні результати.

## 18. GET /paper-statistics

Пов’язана вимога: FR-16.

```http
GET /api/v1/paper-statistics
```

Умовна відповідь 200:

```json
{
  "data": [
    {
      "month": "2026-01",
      "timezone": "UTC",
      "closedTradesCount": 1,
      "grossResult": "0.10",
      "quoteCurrency": "USDT"
    }
  ]
}
```

Правила:

- групування виконується за місяцем закриття в UTC;
- видалені помилкові позиції не враховуються;
- відсутність завершених угод повертає порожній масив;
- результат є навчальним і не враховує торгові витрати.

## 19. Безпечність операцій

- GET-запити не змінюють навчальні угоди або початкові сигнали.
- Сервер перевіряє введення незалежно від браузера.
- Зміни SQLite виконуються параметризованими запитами.
- Відмова не повинна залишати частково виконану операцію.
- Тестування запису виконується на окремій базі.
- Реальні ордери та торгові API-ключі не використовуються.
- Публічне розгортання без додаткового захисту не передбачене.

Політику захисту локальних операцій від небажаних
міжсайтових запитів потрібно визначити до розгортання
і перевірки запитів, які змінюють дані.

- Які точні пороги актуальності даних?

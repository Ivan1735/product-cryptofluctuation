## Результати браузерних сценаріїв

| Сценарій | Фактичний результат | Оцінка |
|---|---|---|
| Коректний RSS HTTP 200 без публікацій | Обидва джерела позначено недоступними; повідомлення про недоступність RSS, 0 статей | Розбіжність, BUG-002 |

| HTTP 503 API новин при першому завантаженні | Залишається skeleton, видимого повідомлення про помилку в блоці немає | Розбіжність, BUG-003 |
| HTTP 503 API новин після успіху | Ручне оновлення показує тимчасовий toast; через 6,5 с він зникає, старий блок і позитивні статуси лишаються без постійної позначки збою | Розбіжність, BUG-003 |
| HTTP 200 з котируваннями від 2020-01-01 | 15 карток, «Binance · наживо», табло показує час UI, а не час отримання котирувань; попередження про застарілість немає | Розбіжність, BUG-004 |
| HTTP 503 цін після успішної відповіді | Є «Немає зв’язку з сервером», збережено картки; справжнього часу отримання біля котирувань немає | Частково правильно; також BUG-004 |
| HTTP 503 цін без кешу | Є повідомлення про відсутність зв’язку, 0 карток; нульові ринкові ціни не вигадано, skeleton залишається | Часткова перевірка; не повний TC-15 |

У цих 8 допоміжних браузерних сценаріях: 1 пройдений, 5 із розбіжностями, 2 часткові. Це **не** підсумок 8 канонічних тест-кейсів. JavaScript pageerror: 0. Три backend-спостереження окремі й не додаються до попередніх 29 методів unittest.

Backend додатково підтвердив:

- успішний порожній RSS і timeout мають однакову класифікацію `source=unavailable`, `feeds.ok=false`;
- дата відсутньої публікації лишається `null`;
- `/api/signals` не позначає застарілі котирування як `live` — перевірено тільки прапорець, не весь процес створення сигналів.

## Докази та відтворення

[Архів доказів](qa-negative-states-evidence.zip) містить:

- `prepare.py`: контрольовані RSS-набори та відповіді Flask test client;
- `browser.cjs`: браузерні сценарії, підміни HTTP, перевірки та знімки;

Скрипти містять шляхи середовища асистента; перед повторним запуском їх треба адаптувати до розташування копії та тимчасової БД. Архів не містить робочої БД чи секретів.

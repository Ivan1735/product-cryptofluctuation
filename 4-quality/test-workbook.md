# Журнал виконання перевірок в Excel

[Завантажити таблицю](CryptoTracker_test_cases_aligned.xlsx).

## Статус

Таблиця підготовлена для майбутнього прогону, не як звіт про успішне тестування.
Усі 37 основних перевірок мають початковий статус «Не виконано».
Виконавці, дати, версії та фактичні результати не вигадуються.

## Джерело та ідентифікатори

Основний аркуш відповідає [тест-кейсам](test-cases.md):
31 функціональний TC та 6 нефункціональних QT.
Повний коміт джерела вказано на аркуші «Як заповнювати».
Після зміни Markdown таблицю потрібно повторно узгодити.

Початкові 37 сценаріїв отриманого Excel збережено окремим архівом
із префіксом SRC. Старі ID наведено для довідки: вони не є ID основного журналу.
Очікування архіву щодо маршрутів, HTTP-кодів та особливостей реалізації
не затверджуються автоматично; їх потрібно перевірити перед використанням.
Архів не входить до підсумку основних перевірок.

## Як виконувати

1. Перевірити передумови, зафіксувати версію та середовище.
2. Для операцій запису підготувати ізольовану тестову базу.
3. Виконати кроки й порівняти фактичний результат з очікуваним.
4. Записати статус, фактичний результат, виконавця, дату та доказ або дефект.
5. Для «Заблоковано» чи «Пропущено» пояснити причину.

Не виконувати скидання або зміни сховища на робочих даних.
Не ставити «Пройдено» лише за наявністю скриншота, коду чи коментаря рев’ю.

TC-01–TC-15 описують сценарії першого MVP. Частина FR-08 у TC-16
перевіряється після включення сигналів. TC-17–TC-31 належать до розширень.
QT мають власні передумови, зокрема щодо реалізованих розширень.

Підсумок рахує статуси основного аркуша. Формули перевірено:
37 «Не виконано», решта статусів — 0, частка пройдених — 0%.
Це перевірка структури таблиці, а не виконання тестів застосунку.
